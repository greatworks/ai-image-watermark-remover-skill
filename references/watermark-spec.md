# 水印规格与实现依据

本文件记录实测数据和取舍理由，供后续维护、调整比例或上架时复核。

## 水印形态

WorkBuddy 图像生成在图片右下角叠加两行半透明白字：

```
AI生成
WORKBUDDY
```

- 位置：紧贴右下边缘，右侧留白约 2% 图宽，底部留白约 1% 图高
- 颜色：白色半透明叠加，像素灰度落在 120~160 区间（随背景亮度浮动）
- 缩放：随画幅等比缩放，不是固定像素字号

水印由客户端强制叠加，生成参数里的 `footnote` 关不掉它——传空字符串同样无效。因此只能事后处理，本技能就是在做这件事。

## 实测

| 画幅 | 水印纵向区间（占图高） | 说明 |
| --- | --- | --- |
| 1536×1024 | 92.9% ~ 98.0% | 逐行亮细节统计，两行文字形成连续带 |
| 1024×1024 | 约 95.2% ~ 99.7% | 目视标定，比例与上者接近 |

结论：水印整体位于底部 8% 以内，且随画幅等比缩放，因此固定 8% 的裁切比例在常见输出尺寸上都成立。

`--ratio` 的安全区间设为 0.02~0.25。低于 0.02 几乎不可能覆盖水印，高于 0.25 会明显破坏构图，两者都会在运行时报错收敛。

## 为什么是裁切而不是修复

- 裁切：无额外依赖、无重绘痕迹、对任意背景稳定；代价是画幅比例轻微变化（1536×1024 → 1536×942，比例 1.5 → 1.63）。
- 修复（inpaint）：需要 OpenCV 及以上级别依赖，半透明文字覆盖区域的纹理重建在复杂背景上容易糊；对普通用户的安装成本过高。

选择裁切。需要保持原始画幅时，由用户自行决定是否接受 8% 的画面损失。

## 幂等标记

重复裁剪会让 8% 变成 16%，因此必须防止二次调用。

| 格式 | 承载方式 | 说明 |
| --- | --- | --- |
| PNG | `tEXt` 文本块 `WorkBuddy-Watermark-Removed=1` | 保存在 `img.info`，可读回 |
| JPEG | EXIF `UserComment`（0x9286） | 与原有 EXIF 合并写入 |
| WebP | EXIF `UserComment` | 同上 |

BMP 与 TIFF 无法可靠携带自定义元数据，若支持会在重复调用时被反复裁剪，因此**不支持这两种格式**，脚本会明确提示格式不支持并建议转换。

`--force` 可以绕过标记强制再裁，用于比例设错后重做。

## 检测算法及其局限

`--detect` 使用形态学顶帽（原灰度图减去 3×3 开运算结果，差值 ≥30 记为笔画像素），统计右下角 ROI（宽 86% 起、高 90.5% 起）内的笔画像素占比。

**它不可靠，只作参考。** 40 张样本的裁前/裁后对照实验中，带水印图得分 0.019~0.032，无水印图得分 0.000~0.022，区间大面积重叠，无法用单一阈值分开。原因是半透明水印的对比度随背景亮度变化：深色背景上水印明显，浅色或高细节背景上几乎无法与背景纹理区分。

因此产品口径固定为：**判据是图片来源，不是检测分数**。AI 生成的图一定有水印，直接裁；检测只用于「用户拿来一张来源不明的图」时的粗略提示。

## 后端矩阵

| 平台 | 主后端 | 降级后端 | 幂等标记 |
| --- | --- | --- | --- |
| 任意 | Pillow | — | 支持 |
| Windows | Pillow | PowerShell + System.Drawing | 降级时不支持 |
| macOS | Pillow | sips | 降级时不支持 |
| Linux | Pillow | 无 | — |

降级后端的存在意义是让没有 Pillow 的机器也能开箱即用（WorkBuddy 自带的 Python 运行时不预装 Pillow）。

Windows 降级后端有两个实现细节必须保留：

1. 临时目录必须建在**目标文件所在磁盘**，否则 `os.replace` 抛 `WinError 17`（跨驱动器移动）。
2. 用 `-File` 传参而不是把长命令塞进 `-Command`，避免路径中的空格与中文被 shell 拆坏。

## 全局规则的落点

WorkBuddy 会把用户级记忆文件（`~/.workbuddy/user-*-personal/MEMORY.md`）注入每个会话。技能把一段带注释标记的规则写进该文件，使「生图后去水印」成为会话级默认行为，而不是只在技能被触发时生效。

- 同一台机器可能有多个用户目录，按修改时间取最新的那个
- 写入前备份为 `MEMORY.md.wm-backup`（已存在则不覆盖，避免连续安装冲掉最初原件）
- 卸载只移除标记块，其余内容原样保留
